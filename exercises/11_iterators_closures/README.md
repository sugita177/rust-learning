# 11_iterators_closures: イテレータとクロージャ（Iterators & Closures）

Rust における関数型プログラミングの中核であり、構文解析（Biome 等）やデータ処理の標準手法である「クロージャ（無名関数）」と「イテレータ（走査器）」、遅延評価（Lazy Evaluation）、ゼロコスト抽象化について学ぶ演習です。

---

## 実行コマンド

```bash
# イテレータとクロージャ演習バイナリの実行
cargo run -p iterators_closures

# コンパイルチェック
cargo check -p iterators_closures
```

## 1. 基本事項・概念の整理

### 1.1 クロージャ（Closures）とは
クロージャとは、変数に束縛したり関数の引数として渡すことができる無名関数です。
- **通常の関数（`fn`）との違い**:
  - 外側のスコープにあるローカル変数を **「キャプチャ（取り込み）」** して内部で利用できる。
  - 局所的に使われるため、引数や戻り値の型注釈を省略でき、コンパイラが 100% 型推論してくれる。

### 1.2 環境キャプチャの3つの方法
所有権と借用のルールに基づき、キャプチャ方法には 3 種類存在します。

| キャプチャ方式 | キーワード | 内部動作 | 外部変数の状態 |
| :--- | :--- | :--- | :--- |
| **不変借用** | （デフォルト） | `&T` として参照 | 外部でも引き続き利用可能 |
| **可変借用** | `mut` クロージャ | `&mut T` として参照 | クロージャ内で値を更新可能 |
| **ムーブ** | **`move \|\| ...`** | 所有権 `T` を奪う | 外部では使用不可（`E0382`） |

### 1.3 イテレータ生成の3つのメソッド
コレクション（`Vec` など）からイテレータを生成する際、借用／所有権の対応関係は以下の通りです。

- **`v.iter()`**: 要素の不変参照（**`&T`**）を走査。元の配列はそのまま残る。
- **`v.iter_mut()`**: 要素の可変参照（**`&mut T`**）を走査。要素の値を直接書き換える。
- **`v.into_iter()`**: 要素そのもの（**`T`**）を消費しながら走査。元の配列はムーブされ消滅する。

### 1.4 遅延評価（Lazy Evaluation）とゼロコスト抽象化
- **遅延評価**:
  - イテレータアダプタ（`map`, `filter` 等）を呼び出した時点では、**実際の計算は 1 ミリ秒も実行されない**。
  - `for` ループや `.collect()`、`.sum()` などの「消費メソッド（Consuming Adaptors）」が呼ばれて初めて、要素が 1 つずつパイプラインを流れる。
- **ゼロコスト抽象化**:
  - メソッドチェーンを多段に繋げても、コンパイル時に手書きの C 言語風 `for` ループと同等（またはループアンローリング等によりそれ以上）の最高速な機械語に展開される。中間配列などの余分なメモリ確保は一切発生しない。

### 1.5 イテレータアダプタと集約
- **`filter(|predicate| ...)`**: 条件に合致する要素のみを通過させる。
- **`map(|transform| ...)`**: 各要素を別の値・型に変換する。
- **`filter_map(|transform| ...)`**: `Option<T>` を返す関数を適用し、`Some(v)` の値だけを取り出して `None` を自動でスキップする。
- **`collect()`**: イテレータを再び `Vec<T>` などのコレクションに集約する。
  - ※ 変換先が多岐にわたるため、`let v: Vec<i32> = ...collect()` のように型注釈が必要。

## 2. 学び・検証記録（コード実装と挙動実証）

### 2.1 [クロージャ実証] 不変借用・可変借用・move キャプチャ
- **検証コード**:
  ```rust
  // ① 不変借用キャプチャ
  let text = String::from("Rust");
  let print_text = || println!("不変借用: {}", text);
  print_text();

  // ② 可変借用キャプチャ
  let mut count = 0;
  let mut increment = || { count += 1; };
  increment();

  // ③ move キャプチャ
  let data = vec![1, 2, 3];
  let consume_data = move || println!("moveキャプチャ: {:?}", data);
  consume_data();
  // println!("{:?}", data); // コンパイルエラー（E0382: borrow of moved value）
  ```
- **実証できたこと**:
  - 不変借用では外部変数が有効なまま保たれること。
  - 可変借用ではクロージャ自体を `mut` にすることで安全に外部変数を更新できること。
  - `move` を付与することで所有権がクロージャ内部に転送され、外側からのアクセスが遮断されることを確認。

---

### 2.2 [遅延評価実証] 出力タイミングの検証
`map` の呼び出し直後と、`for` ループでの消費時におけるログ出力を比較。

- **検証コード**:
  ```rust
  println!("-- mapの定義直前 --");
  let lazy_iter = numbers.iter().map(|x| {
      println!("map実行中: {}", x);
      x * 2
  });
  println!("--mapの定義直後--");

  for n in lazy_iter {
      println!("forループ内での値: {}", n);
  }
  ```
- **実行結果**:
  ```text
  -- mapの定義直前 --
  --mapの定義直後--
  --forループ開始--
  map実行中: 1
  forループ内での値: 2
  map実行中: 2
  forループ内での値: 4
  ```
- **実証できたこと**:
  - `map` の定義直後には一切のログが出力されず、`for` ループで要素が要求された瞬間に 1 つずつ交互に処理が走る「遅延評価」の動作を実証。

---

### 2.3 [パイプライン実証] トークン抽出と集計
文字列スライスから無効なトークンを無視して数値のみを集計する構文解析の基礎パターン。

- **検証コード**:
  ```rust
  let token_input = "100 42 invalid_token 58 -20 skipped_text 10";

  let total: i32 = token_input
      .split_whitespace()
      .filter_map(|token| token.parse::<i32>().ok())
      .sum();
  ```
- **実行結果**:
  ```text
  入力トークン列: "100 42 invalid_token 58 -20 skipped_text 10"
  数値トークンの合計: 190
  ```
- **実証できたこと**:
  - `invalid_token` や `skipped_text` などのパース失敗が `parse().ok()`（`Result` から `Option` への変換）と `filter_map` により安全に弾かれ、`100 + 42 + 58 - 20 + 10 = 190` が正確に一発集計された。
